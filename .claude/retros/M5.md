## The exit criterion, and why it is not a shortfall

*"A device plays a full run over HTTPS against the compose stack."*

1. **No presenter crosses the wire.** M5-15 proved a remote `IGameHost` is *structurally impossible* here — it would acquire an unsatisfiable `IGameHostContractTests` obligation through the adapter glob, and `23` §7.2a forbids a client class implementing a port. So the swap composed `IGameApiPort` and the content socket while all nine presenters still drive `InProcessGameHost`. **M5-17** owns the migration. This is the honest kind of failure: the task discovered the design could not do what its own row promised, said so, and named the row that can.
2. **The HTTPS leg is witnessed nowhere.** Only base address in the client: `http://localhost:8080/`. The compose probes speak plain HTTP. Nothing states whether a shipping client may use a plaintext scheme. Not faked into a suite.
3. **The server image shipped without `game-data/`** — every endpoint below `/health` calls `GameBackbone.Shared`, which `.Require()`s the content set, including `POST /auth/device`. A **second, independent blocker the tracker had never recorded.** Fixed in review with one `COPY`; **unverified**, because no agent may run Docker. The compose-boot job would have caught it — which is precisely what X-07's authored-never-observed CI costs.

## What the whole-milestone pass caught that fifteen per-task reviews could not

Three correctness defects, each spanning two tasks:
- **A stranger could permanently brick another player's run.** `PostgresIdempotencyStore` honoured the scope owner on the record key and dropped it on all three counter statements. A refusal is still a commit, so a foreign player advanced the victim's `last_sequence` and every later legitimate command answered `SEQUENCE_STALE` for ever. Survived because the shared contract suite never varies the owner and that adapter has no fixture at all.
- **A sanctioned player was served their full profile** — one composition root wrapped the account-standing decorator, the other did not.
- **The empty server image**, above.

Plus a client Critical: a refused sign-in retried **once per frame for ever** (~60 anonymous-account registrations a second) while the connection reported `Connected`. Every existing test used a *bounded* refusal budget, so the persistent case had never been driven.

And **five tests that could not fail**, including the recurrence of the exact class M5-13 had already fixed once.
