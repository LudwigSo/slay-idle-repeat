## 2. The defect class this milestone actually had

It was never *"the code is wrong."* It was **"the mechanism that would have caught this quantifies over nothing."**

**Five tasks found live M0-authored defects the moment they gave a rule real subjects** — and every one would have gone **green**, not red:

| Found by | Defect | What would have shipped |
|---|---|---|
| M1-03 | `EmitsCurrencyChanged` counted *touching* a `CurrencyChanged` as *emitting* one | A handler debiting a balance while merely reading an event satisfied `30` §7 and produced no `income_attribution.csv` row — the report answering risk **R10** |
| M1-03 | Authoring `CurrencyChanged` destroyed that rule's own vacuity sentinel | The rule could no longer *say* it was asleep |
| M1-03 | Deleting a **type** row from `SubjectSetFloorTests` passed | The untracked check only ever covered namespaces |
| M1-04 | A public **field** on a snapshot record hashed as **zero bytes** | `RevivesUsed=0` and `RevivesUsed=99` both hash to `fnv1a:96125f0c6eb82a87` |
| M1-05 | `Apply_is_the_only_public_mutation` could not see an exposed collection | `public IReadOnlyList<int> P => _array;` on a `Model/` type |
| M1-06 | A `CommandKind.Meta` handler could hand-write the run's stream counters | Invisible to the fold *and* to the `DeterministicRng` rule |

The review found four more regions **no mechanism reached at all**: `Events` in no layer row, namespace constants in no inventory, the harness seam covering 2 of `Core`'s 10 namespaces, and a presence arm checking `public` but not *constructible*.

**And the fix for one exposed a blind spot in the meta-rule itself.** Widening the constants inventory immediately reported `GuildModelNamespace` as read by nothing — because `Domain.GuildModelNamespace + "."` is **folded by the compiler into one literal**, so the constant's own value never appears in IL. Same family as the hole that let **62 of 63 rules pass while `Core` referenced `Contracts`**, caught only by a csproj *text* rule. Four sightings, three mechanisms. Now **S18**.

**Two Criticals the review found, neither visible to any suite:**

1. **`RequireRunUntouched` compared snapshot records**, whose dictionary components compare by *reference*, while `ToSnapshot()` allocates a fresh copy of a non-empty map. A player mid-run who had watched **one rewarded ad** could send no meta command at all — a P3 violation for a state a correct composition root produces routinely. Green everywhere because the empty-map singleton is the only case any fixture built, **including the negative test named for that exact scenario**.
2. **Nothing validated that the `Run` in a `WorldSlice` belongs to the `Player`.** `30` §4 models `Run` as a child of `Player` in `WorldSlice`'s own doc comment and enforced it nowhere. `Apply(new WorldSlice(playerA, runOfPlayerB), …)` was a legal public call that moved Gold, wrote HP and stamped a run belonging to someone else. **No architecture rule of any shape could have caught it** — a missing domain invariant, not a rule gap.

## 4. 🔒 The planning mistake: waves where lanes were wanted

**This is the milestone's biggest process lesson and it is the conductor's.**

A **wave is a barrier** — everything in it lands before the next starts. A **lane is a dependency chain that runs independently**, and a task starts when *its own* predecessor lands. M1 planned in waves and turned a **5-deep dependency graph into an 11-step queue**.

Concretely: `M1-10` (energy math) depended on nothing the milestone built — it reads M0's tuning — and sat in the third wave purely for batch alignment. `M1-02` waited on a barrier rather than on `M1-06`, the one task it needed. Only 4 of 13 tasks ever ran concurrently.

**And I conflated two axes that are not the same:**
- **Dependency** is hard: B names a type A declares.
- **File contention** is soft: it is a *merge* problem. Wave 3 proved it — two agents editing `SubjectSetFloorTests` with **distinct edit anchors** merged with no conflict. I serialised M1-04/M1-05 over the pin file for no other reason.

Product owner's directive, recorded: **parallelise as much of a milestone as the dependencies allow.** Now **S13c**, and `kickoff-milestone` Phase 4 is rewritten around lanes.
