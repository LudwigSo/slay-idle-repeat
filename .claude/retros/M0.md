## What went wrong

**1. An agent orphaned its own review subagents.** M0-09 ended its turn reporting "the three review agents are still running". Those notifications route to the *conductor*, not the agent — nothing would ever have resumed them. It had to be sent back and the findings hand-forwarded. Had the branch merged as first reported, three cannot-fail blockers would have shipped green.

**2. A wave paired a producer with its consumer.** M0-02 (CI content-validation) and M0-10 (the data it validates) went out in the same wave. Their composition went red on merge: M0-02's orphan check read a schema-authored-ahead-of-its-data as "the schema outlived its content". Sequencing, not luck, should have caught that.

**3. I patched a component another in-flight agent was scheduled to replace.** My `schema-map.json` fix duplicated the mechanism M0-09 was already building (`ContentLoader.SchemasAwaitingContent`). The duplicate then broke 30 real-data tests, because a non-schema `.json` living in `schema/` was itself counted as an orphan schema.

**4. I keyed tracker edits on spec references — twice.** `| 14 §1.1 | ⬜ |` matched both M0-03's row and the X-07 overarching row; `| 14 §14 | ⬜ |` matched both M0-02's and M7-10's. Both times a status landed on an unrelated row. Spec refs are not unique keys; the second instance survived until the review because I did not audit after the first.

**5. I put two fix agents in the same worktree.** One's `git add -A` swept up the other's in-progress files. It caught the mistake itself and recovered cleanly, but the hazard was mine to avoid.

**6. I truncated a skill file and committed the empty version.** Writing the skill amendments, my script opened `kickoff-milestone.md` for writing and then failed mid-encode — `open(w)` truncates immediately, so the file was left at zero bytes — and a `git add -A` in the same step committed it. Restored from history and re-applied, encoding the whole document *before* opening the file. This is a live violation of **S10**, committed minutes after I wrote S10, by the same hand. Two lessons stand: stage explicit paths, and never let a write path truncate before the new content is known-good.

**7. I repeated an unverified number into two dispatch prompts.** M0-10 reported 98 unauthorised nulls; the real figure is **96**. M0-09 counted three independent ways and corrected it. Six documents — including a production XML doc comment — had to be fixed in review.

## The dominant defect class: tests that cannot fail

It appeared in **every suite**, survived per-task review, and was the single largest category in the milestone sweep:

- A keyword-support check that was a string-list comparison and could not see implementation — while **nine enforced keywords had no negative case at all**, used 138 times across 17 real schemas.
- A bounds assertion of `>= int.MinValue`, true of every `int`.
- A weighted-pick ordering test whose 1/99 weights only flip on 2% of the input range — it failed against a *correct* implementation.
- A 96-hole guarantee guarded by four sample references.
- **All 30 real-data negative cases pinned the issue *code*, never which rule fired.** Two confirmed survivors: deleting `"minimum": 1` from `ads.schema.json` — the exact rule one test's name cites — still passed, because a different rule fired at a different pointer. **Uncapped ad rewards would have been shippable with the suite green.**
- `Load_enforces_uniqueItems…` passed with the enforcement deleted, because the invariants layer emitted `DuplicateId` anyway.
- Recursively: **the anti-vacuity meta-rules had vacuous-pass holes of their own.** The placeholder grep scanned a hard-coded directory that returns zero files if renamed; no architecture rule had a floor on its subject set, so renaming `Adapters` to the singular would have turned five rules permanently green.

The fix that generalises: **assert the identity, not the symptom** — the pointer and the rule, not just the error code — and **give every reflection-driven rule a floor on its subject set**.

## What worked and should be copied

- **Self-expiring exemptions.** Five independent inventions of the same idea (`knownEmpty`, the 📐 baseline, `SchemasAwaitingContent`, the snapshot field-order pin, `pendingData`). The pin is the best of them — the only one with a teeth-check against its own permanent vacuity.
- **Externally-validated determinism primitives.** M0-06 generated its reference table from *Microsoft's* xxHash64 implementation, driven by an encoder transcribed from the spec table and never from `Core`, and that generator reproduced the published upstream vectors *before* a row was written. A self-consistent-but-wrong hash would have passed any table generated from itself.
- **Executed spikes beat researched ones.** M0-05a's seven documented failures — above all that a missing `.sln` makes the export **exit 0 with a valid APK containing zero .NET** — could not have been written from documentation.
- **Honest negative results.** M0-05b refused to claim iOS was verified and instead turned an unknown into a measured risk register. That directly enabled D34.
- **Agents pushing back.** The content-pipeline agent rejected one of my findings as partly wrong and was right. The architecture reviewer produced a "will hold under M1 — do not churn" list that prevented needless rework.
