# Retro — M2: Effect DSL & combat simulation

**Milestone:** M2 · 17 tasks + 1 deferred · `milestone/M2`, reviewed on `review/M2`
**Shape:** the first **parallel milestone session** — run concurrently with an unfinished M1, entirely
in worktrees, with the 3-agent cap lifted mid-run by the product owner.
**Result:** 17/17 merged. Clean build · Core 2999 · Application 555 · Contract 24 · Architecture 79/79
· content validation OK · 📐 baseline 46 → 38.

---

## 1. What happened

M2 built the `18` effect DSL and the `05` combat simulator: 44 ops, 23 triggers, 23 conditions, 11
targets, the fixed-tick engine, damage and wards, 12 statuses, enemy derivation, the boss engine, nine
boss scripts as data, PvP duels, the combat log, a determinism baseline and the balance harness.

**Seven waves.** Waves 1–3 ran at the cap of 3. The product owner then lifted the cap and asked for
maximum parallelism; waves 4–5 ran 3 and 4 agents, and waves 6–7 ran one task each because the
remaining work was a genuine dependency chain (boss data needs the engine's authoring contract; the
harness measures everything).

**21 conductor rulings (R1–R21)** were made after the interactive window closed, because `18` §10
explicitly sanctions extending the DSL and the design set left real gaps. One of them (R19) was wrong
and was withdrawn and reissued mid-flight.

**The milestone's most valuable output is not code.** M2-16a's harness ran 1.2 M real boss fights and
found that **no build at par ever takes a boss below 66 % HP** — so every authored phase-2 and
phase-3 mechanic in the game is currently unreachable, and none of `17`'s 27 phase blocks has been
exercised at its intended difficulty. Three of five measurable guardrails fail. That is the first
evidence anyone has had about whether the *game* works, as opposed to whether the code matches a
document.

## 2. What we learned

### 2.1 🔴 One passing mutation proves a rule is **not vacuous** — not that it is **correctly scoped**

This is M2's dominant defect class, by a wide margin. **Nine confirmed cannot-fail tests**, and
**every one was caught by a *second* probe, never the first**:

| # | Mechanism |
|---|---|
| 1–2 | Two anti-cache rules filtered `IsStatic && !IsInitOnly` — a `static readonly Dictionary` slipped past; the IL scan also missed `_memo[k]=v`, which is `callvirt set_Item`, not `stsfld` |
| 3 | A layering probe used a **`const`** — the compiler folds it, so no IL reference exists and the proof passed for the wrong reason |
| 4 | Cecil resolves a `TypeSpecification` to its element type, hiding a `static readonly` struct wrapping a `double[]` |
| 5 | A rule stated over a field's *type* passed over `private static int _drawCount` — `int` is immutable |
| 6 | `A_stunned_actor_does_not_swing` asserted `CanAct` at the fight's **last** tick, i.e. that the stun had *ended*; deleting the gate left it green |
| 7 | An initiative override was a **no-op** on a conventionally indexed roster — the test passed identically with and without it |
| 8 | Four exhaustiveness tests used `Should.NotThrow` over `Enum.GetValues`, satisfied by one `default` arm |
| 9 | A duplicate-id test could not detect its tiebreak's removal: .NET introsort is stable at **≤ 16 elements** and the fixture had fewer |

Plus two more shapes: a positive control whose subject a static initialiser had already validated in
the same process, and a statistical **band** assertion, which passes for a great many broken
simulators unless something proves it can be breached.

**S1 already says "make it fail on purpose". Every one of these did that and still shipped a broken
guard.** The missing half is that the probe must be capable of *distinguishing a narrow rule from a
correct one*. Two of them were also arithmetic-sensitive: a cooldown defect was invisible at 1.0 ASPD
(residue −3.19e-16) and only appeared at 2.0 ASPD.

**When the two-shape discipline was added to prompts mid-milestone, it immediately paid: M2-11's
second probe found #5, and M2-16a's found the band problem.**

### 2.2 🔴 S8 is structural, and no wording can fix it

Reviews were orphaned **three times, by three different mechanisms**:

| Task | Mechanism |
|---|---|
| M2-05 | Backgrounded its reviews and **stopped** |
| M2-10 | Backgrounded its reviews and **deliberately idled**, believing that was compliance — *with the amended rule and its explicit end-of-turn clause in its brief* |
| M2-17 | Did nothing wrong; **the review's channel back to its parent did not exist** (`"No agent named 'general-purpose' is reachable"`) — it reported to the conductor "for relay" |

**All three recoveries found real defects.** M2-05's found both of its new anti-cache rules unable to
catch a cache; M2-17's found a `18` §8 misreading that *"turns a scope decision into a design
prohibition"* plus a new cannot-fail test; M2-10's found five cannot-fail tests and nine code defects.

Mid-milestone the rule was amended — its headline had been written in the conductor's voice
(*"your review subagents report to the conductor, not to you"*), which read by the agent it addressed
licensed exactly the backgrounding it forbade. **The amendment did not prevent instance 2 or 3.**

The reason is mechanical: the harness returns control the moment an agent stops emitting tool calls,
so *"block in the foreground"* describes an outcome the agent cannot directly take. And no sentence
addressed to an agent could have prevented instance 3 at all.

### 2.3 🔴 Parallel agents in one directory cost **semantic** collisions that git merges cleanly

The sharpest data in the milestone:

| Merge | Size | Conflicts | Fixes needed |
|---|---|---|---|
| M2-12 boss engine (alone) | 58 files | **0** | **0** |
| M2-16a harness (alone) | 60 files | **0** | **0** |
| M2-13 boss scripts (alone) | 18 files | **0** | **0** |
| M2-09 (4 siblings in `Rules/Combat/`) | 21 files | 2 | **6** |

**The three largest changes of the milestone merged alone and cost nothing.** Wave 5 put four agents
in `Rules/Combat/` and produced eight hand-resolutions.

**And the expensive ones were not merge conflicts.** Git merged five of six cleanly and the result
then failed to compile, or compiled and failed an architecture rule:

- **M2-02 and M2-08 independently consolidated the same rounding rule into two different primitives.**
  Both diagnosed the same real defect — M2-02 found two of six statements had already drifted, losing
  a `-0.0` normalisation. Two primitives for one rule *is* that defect restated.
- **M2-14 made `IsPvp` derived**, so an invalid state stopped being representable — breaking four
  sibling call sites written against the old shape.
- **M2-09 widened `SetStats` to `AggregatedStats`** to satisfy M2-07's ward-cap obligation, breaking
  M2-10's fixture.
- **Two architecture rules fired correctly on collisions**: an exemption a sibling had satisfied, and
  a stateful-type enumeration blind to types written in the same wave.

Only the compiler and the architecture rules caught these. **In a codebase without that rule
discipline, wide parallelism would have merged them silently.**

One conflict also taught a narrower lesson: `EffectSchemaTests.cs`'s hunk **straddled a method
boundary** rather than sitting between two, so "keep both sides" — correct for the four previous
conflicts — produced 17 compiler errors.

### 2.4 The conductor's error rate is in claims about the **repo**, not the docs

**Ten S9 catches. Eight were against the conductor's own prompts — and every one was a claim about
repo state**, never about a design document: an op-family split, a 📐 marker's location, a platform
list, which baseline entries a task owns, how many collection sources exist, a file's namespace, where
`CanonicalStateWriter` lives. Meanwhile ~100 design numbers transcribed into prompts were correct.

The instruction *"if a number here disagrees with the document or the repo, they win"* is what
surfaced them. It was added after the first catch and every later one came through it.

**R19 is the same failure at ruling level, and the most dangerous single event of the milestone.** I
ruled that effects should be referenced by id, having taken M2-11's genuine finding and jumped to a
solution **without checking what the repo had already decided**. M2-01's committed
`ContentLoader.VocabularySchemas` said the opposite in as many words. It was pasted into two dispatches
as authority and corrected only because M2-10 pushed back with quotations. **It cost nothing solely
because the wave order put the engine before the data — M2-13 had not been dispatched, either time a
ruling of mine was corrected.** That is a favourable accident, not a process.

### 2.5 S4's known limit fired twice, and it is mechanisable

Two `Pending` entries survived their own milestone with a stale owner:
- **`PowerCalculator`** — `Pending (M2-07)`, and M2-07 landed `Rules/Stats/` without it.
- **`EliteModifierEffects`** — written against *"M2-08 / M2-13 — the first consumer"*, and **both
  landed without writing one**.

S4 already documents this: *"an exemption whose reason went stale while still formally valid is not
mechanically detectable. Re-read them at each kickoff."* **The re-read did not happen; both were found
by accident, by tasks doing something else.** But the check is decidable: a `Pending` entry naming a
task the tracker marks 🔍/✅ is stale by construction.

### 2.6 What parallelism genuinely bought

- **R3 was silently dead** — `PHASE`-scoped statuses degraded to `BATTLE`, so **every boss `AURA` did
  nothing** — on a ruling three tasks had been authoring against. Neither M2-10 (owned the scope, had
  no phases) nor M2-12 (owned the phases, would have assumed the scope worked) could have found it
  alone.
- **M2-14 disproved M2-08's handover claim** only because it ran after it and was told to verify.
- Wall-clock: waves 4–5 ran 3–4 agents concurrently against a 17-task milestone.

### 2.7 🔴 "Commit as you go" and the mutation sweep are in direct conflict

After the test-quality pass died producing **zero commits**, I re-dispatched it with an explicit
instruction to *"commit in coherent batches as you go, so progress survives an interruption."*

It was then stopped **mid-mutation-sweep**, and its worktree held three uncommitted **production**
files:

| File | Mutation |
|---|---|
| `BossPhaseController` | `current < reading` → `current != reading` |
| `StatusCadence` | `elapsed > 0` → `elapsed >= 0` |
| `StunWindow` | `if (…)` → **`if (false && …)`** |

Those are S1 probes — deliberately broken code, mid-proof. **Had it followed my instruction one step
earlier, `if (false && …)` would be a commit on a review branch**, and the milestone's stun-immunity
guard — which `05` §5 calls mandatory, *"without it, stun-locking becomes the only viable build"* —
would have been silently disabled in a branch labelled "review fixes".

Git happened to protect us: the mutations were unstaged, so merging the branch could not take them.
That is luck, not design.

**The two instructions are both right and must be scoped against each other:**
- **Commit fixes as you go** — that is what makes an interruption cheap.
- **Never commit during a mutation sweep.** A mutation is reverted before the next commit, always. The
  sweep is atomic: mutate → capture → revert → only then commit.

**And for the conductor: never merge an interrupted agent's branch without diffing its working tree
against `src/`.** This is now the second time an interrupted agent's uncommitted state had to be
classified before it could be trusted — M2-16a's turned out to be applied review fixes worth keeping,
this one turned out to be live mutations that had to be discarded. **The classification is not
optional and cannot be skipped on the assumption that an agent left things tidy.**

### 2.8 Interruptions cost nothing, because of commit granularity

Two agents were killed by a session limit and three review agents by a weekly limit. **M2-09 survived
a hard kill with zero loss** — implementation and both review passes were already committed, and only
the confirmation run was outstanding, which the conductor ran. M2-12 resumed from its transcript with
Phase 1a intact. The review passes that had committed work kept it; the one that had not (test
quality, which died dispatching probes) produced **zero commits**.
